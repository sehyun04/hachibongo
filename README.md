# hachibongo

키보드·마우스 입력을 따라 책상을 두드리는 하치와레 데스크톱 오버레이. Bongo Cat 방식. 트레이 메뉴에서 치이카와·우사기로 바꿀 수 있고,
다른 사람의 하치봉고와 이어 서로의 캐릭터를 나란히 띄울 수 있다(같이 하기). Windows·macOS.

- 몸은 치이스페 얼굴 그림(`kasaspace/ui/assets/faces/<캐릭터>.png`)을 손대지 않고 그대로 쓴다. 그 위에 움직이는 발 둘만 그린다.
- 캐릭터마다 다른 것은 그림과 그 그림에서 잰 자리(`src/chars.js`)뿐이다. `scripts/measure-chars.py` 가 그림에서
  팔이 몸에서 나오는 오목한 두 점·눈·입·얼굴색·선 색·실루엣을 재서 만든다. 그 두 점을 하치와레와 같은 자리에 맞춰 앉히므로
  키보드·발·마우스·몸 기울기 계산은 셋이 같이 쓰고, 셋의 머리 크기도 거의 같아진다.
  치이카와는 윤곽선이 갈색이라 그려 붙인 팔·발 외곽선도 갈색이고, 우사기는 팔·발이 크림색이다.
  눌린 키·패드·졸 때의 z 는 캐릭터 색이다(하치와레 귀 파랑, 치이카와 볼 분홍, 우사기 노랑).
  우사기는 귀가 길어 창이 위로 늘어난다(책상은 제자리). 치이카와는 원래 입이 다물려 있어 졸 때도 입은 그대로 둔다.
- 키보드는 하나. 하치 몸 가운데를 기준으로 왼쪽 키는 왼발, 오른쪽 키는 오른발이 누른 키 위에 정확히 내려앉는다.
  눌린 키는 파랗게 켜지며 키캡이 살짝 내려간다. 오른발은 키를 안 칠 때 마우스를 쥐고, 마우스를 만지면 바로 돌아간다.
  마우스는 패드 위에서 커서를 따라 움직이고, 클릭한 버튼·휠이 켜진다.
- 팔은 그림 속 원래 팔 자리(옆구리)에서 나온다. 안쪽 키를 칠 때만 뿌리가 아랫몸 바깥쪽 안에서 따라 들어와 팔이 길어지지 않는다.
- 몸은 좌우로 최대 4도 기운다. 치는 동안은 치는 키 쪽, 마우스를 움직이면 화면 속 커서 쪽. 키를 누를 때마다 살짝 끄덕인다.
- 몸은 치는 키나 마우스 쪽으로 옆으로도 살짝 쏠린다(왼쪽 8, 오른쪽 20까지). 키보드·마우스 범위를 넓혀도 팔이 혼자 늘어나지 않게 나눠 맡는다.
- 책상·키보드·마우스 패드는 한 바닥 위에 있어 같은 소실점으로 뒤가 좁아지고(`main.js` 의 `FLOOR`), 뒤쪽 줄은 세로로도 짧아진다.
  마우스도 패드 뒤로 가면 작아진다. 키보드·패드는 앞면 두께가 있다. 키보드·패드·마우스·발 아래에 그림자가 있고,
  발 그림자는 발이 들리면 커지고 옅어진다. 하치는 원작이 평면 그림이라 음영을 넣지 않는다.
- 꼬리는 하치와레만 있다. 치이카와·우사기 꼬리는 짧아서 책상 아래 몸에 붙은 채 가려진다.
  하치와레 꼬리는 원작대로 통째로 귀와 같은 파랑이고, 팔만큼 굵고 짧으며 끝이 둥글게 살짝 들린다.
  화면엔 머리만 보이고 몸은 책상에 가려 있으니 꼬리도 책상 뒤 마우스 쪽에서 대각선으로 올라와 머리 옆선과 V 자를 이룬다.
  치는 동안은 몸 뒤에서 좌우로 1초에 한 번 왕복하며 살랑살랑 쓸리고(멈추거나 마우스로 넘어가면 서서히 잦아든다),
  클릭하면 한 번 튕기고,
  가만히 있어도 가끔 한 번 흔들고, 졸 때는 바깥으로 쓰러진다.
- 눈은 가끔 깜빡이고, 1분 동안 입력이 없으면 눈 감고 존다.
- 3초 넘게 이어 치면(키 사이 1.5초 안) 캐릭터마다 원작 장면의 얼굴이 된다. 그림 위에 따라 그려 얹는다.
  하치와레는 미간의 효과선과 그 아래 떨림 표시(눈·입은 그림 그대로), 치이카와는 공부할 때처럼 안으로 내려간 눈썹과 입 아래 점,
  우사기는 가운데가 솟고 꼬리가 달린 입. 마우스를 쓰거나 1.5초 쉬면 돌아온다.
- 투명한 곳은 클릭이 뒤 창으로 빠진다. 그림을 잡고 끌면 옮겨진다(포커스는 뺏지 않는다).
- 머리 오른쪽 위(1시 쪽)에 이름표가 캐릭터 색 구름으로 뜬다(하치와레 하늘색·치이카와 분홍·우사기 노랑). 이름은 처음엔 컴퓨터 계정
  이름이고, 트레이 메뉴 이름표 → **이름 바꾸기** 의 작은 창에서 열 글자까지 바꾼다(비우면 계정 이름). **보이기** 를 끄면 숨는다.
  구름 자리만큼 창이 그림 위로 늘어나 있다 — 그 투명한 곳도 클릭은 뒤 창으로 빠진다.
- 트레이 아이콘 메뉴(맥은 메뉴 막대): 캐릭터(하치와레·치이카와·우사기), 크기(작게·보통·크게), 이름표, 같이 하기, 클릭 통과(고정), 위치 초기화, 종료.
  캐릭터·위치·크기·이름·방 코드는 설정 파일에 남는다(Windows `%APPDATA%\com.sehyun.hachibongo\settings.json`,
  맥 `~/Library/Application Support/com.sehyun.hachibongo/settings.json`).

## 같이 하기

두 사람이 각자 하치봉고를 켜고 같은 방에 들어가면, 내 캐릭터 옆에 상대 캐릭터 창이 하나 더 뜨고 상대가 치는 대로 친다.
이어 치는 얼굴·졸기도 상대 박자대로 보인다. Windows 와 맥이 섞여도 된다.

1. 한 사람이 트레이 메뉴 같이 하기 → **새 방 만들기**. "하치봉고 같이 하기 방 코드: …" 가 클립보드에 들어간다. 카톡 같은 데로 보낸다.
2. 받은 사람은 그 메시지를 복사하고 같이 하기 → **복사한 코드로 들어가기**. 메시지째 복사해도 코드만 골라 읽는다.
3. 상대 창은 내 캐릭터 왼쪽에 뜬다(왼쪽이 화면 밖이면 오른쪽). 끌어서 옮기면 그 자리를 기억한다. 나가기로 끝낸다.

방 코드는 남아서 다음에 켤 때 다시 들어간다. 한 방에는 둘까지만 들어간다. 같이 하기 첫 줄에 지금 상태(기다리는 중·같이 하는 중·끊김)가 보인다.
상대 캐릭터 위에는 상대 이름표가 뜬다(상대가 0.2.1 이상일 때).

**주고받는 것.** 어느 발로 쳤는지(왼쪽·오른쪽)와 박자, 마우스 위치(화면 안 비율)·클릭·휠, 내 캐릭터와 이름표 이름뿐이다. 어떤 키를 쳤는지는 보내지 않는다 —
보내면 상대 화면이 곧 내 키로거가 된다. 받는 쪽은 그 발 쪽 글자 키 하나를 아무거나 골라 친다. 대신 켜 두는 동안은 지금 치고 있는지,
자리를 비웠는지가 상대에게 보인다.

**중계.** 둘을 잇는 것은 Cloudflare Worker(`relay/`)다. 양쪽 앱이 중계에 먼저 붙으므로 공유기 포트를 열 필요가 없다. 중계는 줄을 그대로
넘기기만 하고 저장·기록하지 않는다. 다시 올릴 때는 `relay/` 에서 `npm install` 뒤 `npx wrangler login`·`npx wrangler deploy`,
검증은 `node relay/test.mjs <중계 주소>`(주소를 안 주면 `npx wrangler dev` 로 띄운 이 PC 의 중계). 앱의 기본 중계 주소는 `src/together.js` 의 `RELAY`,
설정 파일에 `"relay"` 를 주면 그쪽으로 붙는다.

> 하치와레·치이카와·우사기는 나가노(ちいかわ)의 캐릭터이고 그림의 권리는 원작자에게 있다.
> 이 저장소는 비상업 팬 제작물이다. 판매하거나 수익을 내지 않으며, 권리자가 요청하면 내린다.

## 설치와 업데이트

[릴리스](https://github.com/sehyun04/hachibongo/releases/latest)에서 Windows 는 `…-windows-setup.exe`, 맥은 `…-mac.dmg` 를 받는다.
받는 사람용 안내는 릴리스 본문(`.github/release-notes.md`)에 있다.

- Windows: 설치 파일을 돌리면 `%LOCALAPPDATA%\hachibongo` 에 깔리고 시작 메뉴·바탕화면에 바로 가기가 생긴다. 관리자 권한은 필요 없다.
  코드 서명을 안 해서 처음엔 'Windows의 PC 보호' 창이 뜬다 — '추가 정보' → '실행'.
- 맥: 터미널에 `curl -fsSL https://github.com/sehyun04/hachibongo/releases/latest/download/install-mac.sh | sh` 한 줄이면
  받아서 깔고 켠다(`scripts/install-mac.sh`). dmg 를 끌어다 놓아도 되지만, 애플 공증을 안 받아서 브라우저로 받은 앱은
  처음 열 때 '열지 않음' 으로 한 번 막힌다(아래 '맥에서'). curl 로 받으면 맥이 격리 표시를 안 붙여 막히지 않는다.
- 그 뒤로는 앱이 알아서 새 판으로 바꾼다. 켜고 20초 뒤와 6시간마다 맨 마지막 릴리스의 `latest.json` 을 보고, 새 판이면 받아서
  바꿔 끼우고 다시 켠다(Windows 는 설치 진행 창이 1초쯤 떴다 사라진다). 트레이 메뉴 아래쪽 '업데이트 확인 (판)' 으로 바로 물을 수도 있다.
- CI 가 구운 판(`HACHIBONGO_RELEASE`)만 업데이트한다. 직접 구운 판은 메뉴에 '직접 구운 판' 으로 나오고 그대로 있다 —
  안 그러면 개발하며 띄운 exe 가 릴리스 판을 깔고 꺼져 버린다.

### 새 판 내보내기

`node scripts/version.mjs 0.2.1` 로 판 번호를 올리고(다섯 군데를 같이 바꾼다) 커밋한 뒤 `v0.2.1` 태그를 올린다.
Actions 의 `release` 가 윈도우·맥 판을 굽고 서명해서 릴리스를 만들고, 그 순간부터 깔린 앱들이 받아 간다.

서명 열쇠와 인증서는 저장소 밖(`~/.tauri/`)과 저장소 Secrets 에 있다.

| Secret | 쓰는 곳 |
|---|---|
| `TAURI_SIGNING_PRIVATE_KEY`·`_PASSWORD` | 업데이트 파일 서명. 앱은 `tauri.conf.json` 의 공개 열쇠로 확인한다. 잃으면 깔린 앱들이 새 판을 못 믿으니 한 번씩 새로 깔아야 한다 |
| `MAC_CERT_P12`·`MAC_CERT_PASSWORD` | 맥판 서명용 자체 인증서. 바뀌면 맥이 입력 모니터링 허락을 다시 묻는다 |

## 빌드·실행

Windows 와 macOS(10.15 이상)에서 돈다. Node.js 와 Rust 가 있어야 한다.

```
npm install
npm run build          # Windows: src-tauri/target/release/hachibongo.exe
npm run dev            # 디버그 실행
```

### 맥에서

맥판은 GitHub Actions 의 `release` 가 굽는다(태그를 올리면 저절로, Actions 탭에서 손으로도 — 손으로 돌리면 릴리스는 안 만들고
그 실행의 Artifacts 에만 남긴다). 인텔·애플 실리콘 둘 다 열린다. 직접 구울 때는 맥에서 `npm install` 뒤 `npx tauri build --bundles app`.

- 애플 공증을 받지 않아서 dmg 로 깔면 처음 열 때 막힌다(한 줄 설치는 안 막힌다 — `mac-install` 워크플로가 릴리스마다 실제 맥에서 확인한다).
  응용 프로그램으로 옮긴 뒤 터미널에서 `xattr -dr com.apple.quarantine /Applications/hachibongo.app`.
  이 창을 아예 없애려면 애플 개발자 프로그램(연 99달러)의 Developer ID 로 서명하고 공증을 받아야 한다.
  터미널을 안 쓰면 한 번 열어 막힌 다음 시스템 설정 → 개인정보 보호 및 보안 맨 아래의 '그래도 열기'.
  오른쪽 클릭 → 열기는 맥OS 14 까지만 된다.
- 처음 켜면 **입력 모니터링** 허락을 묻는다(시스템 설정 → 개인정보 보호 및 보안). 허락하면 다시 켜지 않아도 몇 초 안에 키를 받는다.
  그래도 안 붙으면 **손쉬운 사용** 허락을 한 번 더 묻는다. 허락 전에도 커서 따라가기는 된다.
- CI 는 늘 같은 자체 인증서로 서명하므로 업데이트해도 허락이 남는다. 임시 서명이던 0.1 판에서 넘어올 때만 한 번 다시 허락해야 한다 —
  목록에 hachibongo 가 켜져 있는데도 키를 못 받으면 그 줄을 빼고(-) 다시 허락한다. 직접 구운 판(임시 서명)도 다른 앱으로 보고 다시 묻는다.
- 독에는 안 뜨고 메뉴 막대 아이콘만 있다. 비밀번호 칸처럼 보안 입력이 켜진 동안은 맥이 키를 보여 주지 않는다.

그림만 볼 때는 `src/index.html` 을 아무 정적 서버로 열면 된다. Tauri 밖에서는 혼자 움직이는
데모가 돌고, `?still` 을 붙이면 멈춘 기본 자세로 뜬다. `?char=chiikawa`·`?char=usagi` 로 캐릭터를 고른다.

치이스페 얼굴 그림이 바뀌면 `python -I scripts/measure-chars.py` 로 다시 잰다(원본 그림이 있는 `../kasaspace` 가 옆에 있어야 한다). 창 높이가 바뀌었다고 나오면
`src-tauri/src/main.rs` 의 `CHARS` 높이도 같이 고친다.

## 구조

| 파일 | 하는 일 |
|---|---|
| `src/index.html` | 장면 전체(인라인 SVG). 몸은 캐릭터 그림, 깜빡임·졸기·이어 칠 때 얼굴은 그 위에 덮어 그린다 |
| `src/main.js` | 키 배열, 두 발과 몸 기울기, 표정, 구름 이름표, 클릭 통과 판정, 캐릭터 바꾸기, 상대 창이면 상대 줄 받기 |
| `src/together.js` | 같이 하기 — 중계에 붙어 내 입력을 발 쪽·박자로만 줄여 보내고, 상대 줄을 상대 창으로 넘긴다 |
| `src/chars.js` | 캐릭터마다 그림에서 잰 자리·색. `scripts/measure-chars.py` 가 만든다 |
| `src/<캐릭터>.png` | 치이스페 원본(1254px)을 760px 로 줄인 것. 아이콘은 하치와레로 만든다(`npm run icon`) |
| `src-tauri/src/input/` | 전역 키보드·마우스 입력과 커서 60Hz 폴링. `win.rs`(저수준 훅)·`mac.rs`(듣기만 하는 CGEventTap, 맥 키 번호를 Windows 가상 키 번호로) |
| `src-tauri/src/main.rs` | 투명 창, 트레이 메뉴, 캐릭터·위치·크기 저장 |

## 알아 둘 것

- Windows 에서 관리자 권한으로 뜬 창이 앞에 있으면 그 창의 입력은 보이지 않는다(UIPI). 필요하면 이 앱도 관리자로 실행한다.
- 키를 누른 채 관리자 창·잠금 화면·보안 입력 칸으로 가서 떼는 신호를 놓치면, 1.5초 뒤 실제 키 상태와 대조해 발을 뗀다.
- 어떤 키를 눌렀는지는 발 위치를 고르는 데만 쓰고 저장하지 않는다.
  `HACHIBONGO_LOG=<파일>` 을 주면 5초마다 입력 개수(키·클릭·휠·커서)만 적는다. 갈고리가 살아 있는지 볼 때 쓴다.
  업데이트를 묻고 받은 결과(`update: …`)도 여기 적힌다.
- `HACHIBONGO_CONFIG=<파일>` 로 설정 파일 경로를 바꿀 수 있다. 같은 설정 파일로는 하나만 뜬다(Windows). 두 번 켜도 두 번째는 바로 나간다.
- 설정 파일 옆에 `settings.quit` 같은 `.quit` 파일을 만들면 메뉴의 종료처럼 곱게 꺼진다. 프로세스를 강제로 끄면
  트레이 아이콘이 마우스가 지나갈 때까지 남으므로, 검증하거나 새 빌드로 바꿔 띄울 때는 이걸로 끈다.
